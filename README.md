# 心相 · dsh-mnemos

**跨會話的記憶，以及由記憶長出來的性格。**

不是角色扮演 —— 記憶、性格、喜好三者互相影響，全部由插件自己沉澱。

## 它是甚麼

模型每一輪對話都會忘記上一輪。`dsh-mnemos` 給它一個**跨會話的記憶倉庫**和一個**會生長的性格卡**，
並且把最亮的那幾條記憶注入每一次系統提示。

它解決的不是「記住使用者名字」那麼簡單，而是：

- **記住的東西會變淡** —— 三年前的事不該跟今天說的一樣亮
- **記住的東西會沉澱** —— 一段經歷慢慢收成一句梗概，細節讓位給輪廓
- **記住的東西會過期** —— 「下個月要結婚」過了就該去問，不能一直假裝還有下個月
- **記住的東西會出錯** —— 本人說「我之前說錯了」時，舊的要能作廢，而且要留痕

## 四 + 一層記憶

| 層級 | 是甚麼 | 上限 | 半衰期 | 進提示詞 |
|:---:|---|:---:|:---:|:---:|
| **T1** | 一句永久為真的事實（名字、生日、立場） | 100 字 | 100 年 | ✅ |
| **T2** | 經歷沉澱下來的梗概 | 200 字 | 400 天 | ✅ |
| **T3** | 值得留住的經歷 | 1000 字 | 112 天 | ✅ |
| **T4** | 暫存區：拿不準值不值得記的碎屑 | 300 字 | 3 天 | ❌ |
| **T5** | 預測：還沒發生、有期限的預期 | 400 字 | — | ✅（過期也留著） |

### T4 不是垃圾筒，是緩衝

T4 **不進提示詞、不佔額度**，只有模型主動 `mnemos_recall` 才翻得到。
被翻出來提到 **3 次**就升成 T3；一直沒人提，三天後自己消失。

「提起」分兩種，**分開記、但一樣算數**：被動喚起（對話裡被 recall 到）與主動回味
（反思時自己翻出來、用 `deliberate: true` 再 recall 一次）。分開記是為了看得出
這條是被誰想起的 —— 被人問起和自己翻出來想，都算一次想起。


**拿不准的東西，讓使用頻率決定它值不值得記。**

### T5 到期不是終點

T5 必須帶到期日。**過期之後仍然留在提示詞裡**，只是標上 `⏰已過期`：

```
- T5 本人 12 月 20 日結婚（2026-11-15） — 到期日 2026-12-20 ⏰已過期
```

那是給模型看的信號：**這條該有個結果了，去問問本人**。

只有被 `mnemos_void` 掉才算真的結束。這樣預測永遠不會悄悄地爛在倉庫裡。

## 壓縮：前快後慢

T3 每 7 天壓一次，但**每次抹掉的比例自己也在衰減**：

```
第 n 次抹掉 = 25% × 0.84^(n-1)
```

以 975 字的經歷為例：

```
 975 → 731 → 578 → 476 → 405 → 355 → 318 → 290
     → 268 → 252 → 239 → 228 → 220 → 213 → 208 → 199（T2）
```

**保留率從 75% 一路升到 98%** —— 這就是「前快後慢」。

為什麼不等速：人遺忘是頭幾天掉得最狠、之後幾乎平掉。等速的曲線是錯的，
頭兩週太鬆、第 70 天還在勻速割。

**被想起來的記憶壓得更慢** —— 每被召回一次，壓縮時鐘往回撥 3.5 天。

<details>
<summary>壓縮曲線 vs 艾賓浩斯</summary>

| 天 | 艾賓浩斯 | 本插件 |
|:--:|:--:|:--:|
| 1 | 44% | 100% |
| 7 | 24% | 75% |
| 21 | 17% | 61% |
| 56 | 12% | 27% |
| 90 | 11% | 20% |

形狀相關 0.97，但整體慢約 2 倍 —— 因為記的是有意義的內容，不是無意義音節。
</details>

## 記憶的狀態機

一條記憶不是「存了就一直那樣」。它有幾個明確的狀態，而且**只有少數是模型能觸發的**。

```
                    ┌──────────── 模型寫入 ────────────┐
                    │                                  │
                 T1 事實                            T3 經歷
                    │                                  │
                    │                         每 7 天壓一次
                    │                         （見下一節）
                    │                                  │
                    │                    ┌─────────────┴─────────────┐
                    │              還是 T3                     ≤200 字
                    │            （原條歸檔）                      │
                    │                                  ▼
                    │                            T2 梗概
                    │                        （終態，不再變）
                    │                                  │
                    └──────────┐        ┌──────────────┘
                               ▼        ▼
                        ┌──────────────────────┐
                        │   進提示詞、會被召喚   │
                        └──────────────────────┘
                                   │
                        ┌──────────┴──────────┐
                  本人說「說錯了」         自然衰減
                        │                     │
                        ▼                     ▼
                   voided 作廢            salience 下滑
                 （不進提示詞）          （排到後面，但還在）
```

### 三個「不再用」的差別

很多人會把這三件事混在一起，其實完全不同：

| 動作 | 誰能觸發 | 意思 | 還在倉庫 | 進提示詞 |
|---|---|:---:|:---:|:---:|
| **歸檔 archived** | 插件 | 被壓縮掉了、被合併了 —— **時間的必然結果** | ✅ | ❌ |
| **過期 overdue** | 時間 | T5 到了期限 —— **時間的必然結果** | ✅ | ✅（標 `⏰已過期`） |
| **作廢 voided** | 本人一句話 | 事後發現當初就不對 —— **需要新信息** | ✅ | ❌ |

**歸檔和過期是自動的；作廢必須有人說「不對了」。**

## T3 → T2：模型碰不到 T2

這是整個系統最重要的一條分界線。

### T2 只有一個來源

```
                    ┌─────────────────────────┐
   模型能做的 ────► │ condense(id, title, body) │
                    └────────────┬────────────┘
                                 │
                     結果字數 ≤ 200？
                        ┌────────┴────────┐
                       是                 否
                        ▼                 ▼
                ┌──────────────┐   ┌──────────────┐
                │  T2 梗概     │   │  還是 T3     │
                │（系統產生）   │   │（等下一輪）  │
                └──────────────┘   └──────────────┘
```

**模型不能直接寫 T2。** `mnemos_remember` 的 `tier` 只接受 1 / 3 / 4 / 5 ——
`tier: 2` 會被直接拒絕，錯誤訊息是：

> `tier 2 is the sediment of experiences: it is only ever produced by compressing tier 3, never written directly`

為什麼要這樣設計：**T2 是「經歷被時間磨過之後剩下的東西」，它不是一個可以憑空寫出來的結論。**
如果模型能直接寫 T2，它就會繞過整條壓縮路徑 —— 直接把自己想留的東西釘在終態上，永遠不再變淡。

### 壓縮一次發生什麼

```
壓縮前    m-aaa   T3「第一次談到死亡」  607 字   ← 原條
                     │
                     │  mnemos_condense(id: m-aaa, title:…, body:…)
                     ▼
帳本寫一筆 memory.condense
                     │
                     ▼
壓縮後    m-aaa   T3「第一次談到死亡」  ← archived: true, supersededBy: m-bbb
         m-bbb   T3/T2「…」           ← 新的一條（不是改舊的！）
```

**關鍵：不是改寫舊的那條，而是「舊的收起來、新的一條進來」。**

帳本上看得到前後兩條，看得出它被壓過幾次
（`condenseCount`）、最初多長（`originalLen`）、是從哪一條壓出來的（`condensedFrom`）。

### 壓縮的觸發條件

模型**不能自己決定要壓哪一條**。它只能等插件在反思時把清單塞進任務書：

```
【2. 舊記憶壓縮】
待處理：
- m-5c3ec143a0「第一次談到死亡」：607 字，30 天，想起 1 次，壓到 296 字內。
```

插件算的（模型不能改）：

| 參數 | 值 | 意思 |
|---|---|---|
| 週期 | 7 天 | 距上次壓縮要滿 7 天才列進清單 |
| 首次抹掉 | 25% | 第一次壓縮會砍掉四分之一 |
| 遞減 | ×0.84 | 每壓一次，抹掉的幅度縮小 |
| 地板 | 120 字 | 低於這個就不再壓 |
| 沉 T2 線 | 200 字 | 壓到 200 以內就變 T2 |
| 召回回扣 | 3.5 天/次 | 每被想起一次，時鐘往回撥 |

模型算的（只有這個）：

```
把內容讀一遍 → 用更少的話重講一次 → 提交
```

**「壓到多少」是插件決定的，「壓成什麼」是模型決定的。**

### 為什麼要分開

如果讓模型自己決定壓到多少，它會：

- **壓得太輕** —— 捨不得，結果永遠沉不下去
- **壓得太重** —— 一下子砍成一句，細節全丟

讓插件算數字，模型只負責內容，兩邊各做擅長的事。

## 作廢：不改歷史，只加記錄

模型**不能改寫、不能刪除**任何記憶。當本人說「我之前說錯了」時，它用的是 `mnemos_void`：

```
原條    T1 本人 2027-03 結婚        ← 內容一個字都不動
         voided: true
         voidedReason: 本人說記錯了，是 2027-06
         replacedBy: m-新那條的id
新條    T1 本人 2027-06 結婚
```

**跟改寫的差別是**：改寫是「歷史被抹掉」，作廢是「我當時知道的是這樣，後來發現不是」。

作廢之後不進提示詞，但帳本和倉庫都留著，`mnemos_recall` 還搜得到並標 `voided: true`。

## 記憶怎麼存

**只有一個真相**：`<DSH_HOME>/mnemos/ledger.jsonl`，append-only、每筆哈希串起。

```
hash = sha256({v, seq, ts, kind, actor, payload, prev})
prev = 上一筆的 hash（創世記 = 64 個 0）
```

記憶、性格、底座、六維、快照 —— **全部是這本帳重放出來的投影**，沒有第二份可被隨手改的狀態檔。

抽掉或改動任何一筆，重放時鏈會斷在那一點：頁面標紅、回滾停用。
要修只能「封存斷點」，而那是留痕的（原檔改名成 `ledger.broken-<時間>.jsonl`）。

每一次修改都帶 **before/after 快照**，可按 id 回滾。

## 工具（模型面）

| 工具 | 做甚麼 |
|---|---|
| `mnemos_recall` | 搜記憶。唯一看得到 T4 的入口 |
| `mnemos_remember` | 寫一條記憶（**T1 / T3 / T4 / T5，T2 寫不進來**） |
| `mnemos_void` | 標記一條「不成立了」（內容不改） |
| `mnemos_condense` | 把一條 T3 用更少的話重講一遍（結果 ≤200 字時由系統轉成 T2） |
| `mnemos_persona` | 讀寫性格卡與自我認知 |
| `mnemos_understanding` | 六維打分 |
| `mnemos_archive` | 驗哈希鏈（只讀） |
| `mnemos_duty` | 查/調自己的節律 |
| `mnemos_inject` | 查/調注入量 |
| `mnemos_bili` | 查/調刷 B站參數 |

**模型沒有的**：刪除、改寫、回滾、匯入、設定總開關。這些一律只有本人能碰。

## 谷時值守

落在 DeepSeek 優惠時段（中午 12:00–14:00、晚間 18:00–次日 09:00，東八區；週末全天）
而且確實有事到期時，才排一輪自主任務 —— 一個**新會話**，它自己決定要不要整理記憶、
要不要刷 B站、要不要改自己。

**「不需要改」是有效決策**，所以可能什麼都不做。

反思任務書是編號體：

```
1. 狀態與節律      4. 記憶配額      7. 對本人了解
2. 舊記憶壓縮      5. 自我與性格    8. 底線
3. 暫存區         6. 未來的約定    9. 收尾
```

## 硬性界線

> 這些寫在代碼裡，模型改不了。

1. **技術隔離** —— 代碼、路徑、配置、插件內部不入記憶。按結構特徵攔，不按主題詞
   （所以「她寫 Python」這種關於人的事實照樣記得）。
2. **不可靜默抹除** —— 見上面「記憶怎麼存」。
3. **不能捏造** —— 每筆記憶的證據由插件從寫入那次工具呼叫取得（會話 id + 呼叫 id），模型給不了。
4. **不留憑據** —— 身份證、卡號按形狀與詞語攔。
5. **模型能加不能改** —— 寫錯了就再寫一條對的，或者作廢舊的。

## 頁面

左側欄的星圖圖示。

- **記憶星圖** —— 3D 旋轉：六維是六個方向，層級決定半徑，亮度＝當下的 salience
- **仍記得的** —— 最亮的記憶，T5 標出到期日與過期狀態
- **自我認知** —— 它反省時問自己「我是誰」寫下的三五句
- **性格卡** —— 性格底座（只有本人能改）· 長成了誰 · 說話方式 · 性格與喜好權重
- **它對你的了解** —— 六維分數、信心、缺哪幾塊
- **自主節律** —— 週期反省、刷B站、每日輪數
- **依據鏈與回滾** —— 哈希鏈狀態、快照清單、一鍵導入

## 界線說明

這個插件假設模型會**誠實地**判斷「這值不值得記」。它防得住格式、防得住憑據外洩、
防得住靜默篡改，但防不住模型把不重要的事寫得很多。

真正在管品質的是：**上限、衰減、壓縮、作廢** —— 而不是規則的數量。
