# dsh-silt

[English](README.en.md)

> 跨會話記憶與人格插件 · 版本 `v1.7.0` · 2026-11-15

`dsh-silt` 是為 DSH 宿主進程打造的長期記憶與人格成長引擎。它讓模型擁有一份會自我演化、分層沉澱、可被追問的記憶，以及一張由對話親手「長出來」的性格卡。

</div>

模型每一輪對話都會忘記上一輪。這個插件給它一個跨會話的記憶倉庫，和一個會生長的性格卡。

它不只解決「記住名字」，還解決四件事：

- **會變淡** —— 三年前的事不該跟今天說的一樣亮
- **會沉澱** —— 一段經歷慢慢收成一句梗概
- **會過期** —— 「下個月要結婚」過了就該去問
- **會出錯** —— 本人說「我說錯了」時，舊的要能作廢且留痕

## 記憶分五層

| | 是甚麼 | 上限 | 半衰期 | 進提示詞 |
|:--:|---|:--:|:--:|:--:|
| **T1** | 永久為真的事實（名字、生日、立場） | 100 | 100 年 | ✅ |
| **T2** | 經歷沉澱下來的梗概 | 200 | 400 天 | ✅ |
| **T3** | 值得留住的經歷 | 1000 | 112 天 | ✅ |
| **T4** | 暫存區：拿不準值不值得記 | 300 | 3 天 | ❌ |
| **T5** | 預測：還沒發生、有期限 | 400 | — | ✅ 過期也留 |

---

**T4 是緩衝，不是垃圾桶** —— 不進提示詞。每次被想起來，由模型自己說「這一提有多重」（0–0.5），
累積到 1 就升 T3；沒人想起就自己散。

為什麼不是「提三次就升」：三次是次數，不是份量。「他今天又提到那個名字」和「他突然問起那件事」
都算一次，但不該一樣重。份量只有模型說得出來，插件只負責把它加起來。

**T5 過期不是終點** —— 過期後仍留在提示詞裡，標 `⏰已過期`，逼模型去問結果。
只有被作廢才真正離開。

```
- T5 本人 12 月 20 日結婚（2026-11-15） — 到期日 2026-12-20 ⏰已過期
```

## 系統特點

**1. 遺忘發生在內容上，不只是排序**

多數系統的衰減只決定「誰先進提示詞」，記憶本身一個字沒少。這裡的 T3 每 7 天真的被重講一次，
目標長度沿一條冪律往下走（`初長 × (1 + 0.14·T/s)^-0.5`），約 162 天沉成 T2。

遺忘是有內容損失的，不是換個位置。

**2. 想起來會延後遺忘**

每被召回一次，時間軸拉長到 `1.2^R`（上限 10 次）。被想起十次的記憶，要 **1002 天**才沉成一句話；
從沒被想起的只要 162 天。

跟加權排序不同：加權只讓它更容易被選中，這裡是讓它**更慢變短**。跟間隔重複效應同向，
但機制是「把時間軸拉長」而非「強化提取」。

**3. 預測有到期日，而且過期不自動消失**

T5 帶 `expiresAt`，粒度可以只到年或月。過期後仍留在提示詞裡，標 `⏰已過期`——只有被作廢才離開。

一句過期的預測不該悄悄爛在倉庫裡。到期不是終點，是「這條該有個結果了」的信號。

**4. 作廢，而不是改寫**

本人說「我記錯了」時，原條標題正文一個字都不動，只加 `voided` / `voidedReason` / `replacedBy`。

改寫是歷史被抹掉；作廢是「我當時知道的是這樣，後來發現不是」。作廢後不進提示詞，
但 `recall` 仍搜得到並標 `voided: true`。

**5. 升級看份量，不看次數**

T4 升 T3 的判據是置信度累加到 1.0，每次召回由模型給 0–0.5。單次上限刻意小於門檻——
一次想起不足以讓碎屑變成經歷。

因為三次是**次數**，不是**份量**。「他今天又提到那個名字」和「他突然問起那件事」都算一次，
但不該一樣重。

配套的一條：反思時掃 T4 要帶 `confidence: 0`，否則光是掃一遍每條都加 0.2，
碎屑會被「掃描」這個動作本身催熟。

**6. 盲區是明示的**

只注入標題，正文按需 `recall`。擠不進去時末尾明說「另有 N 條沒顯示」，`silt_unseen` 可以一頁頁翻。

沒有這一行，模型會以為「我記得的就這些」——既不會去查，也不會承認自己有盲區。
這把「預算不夠」從**丟失**變成了**延後取用**。

## 壓縮：前快後慢

T3 每 7 天壓一次。目標字數不是「每輪固定抹掉多少」，而是一條**冪律曲線**：

```
target = 初長 × (1 + 0.14 × T/s)^(-0.5)

T = 從誕生起的總天數
s = 1.2^R，R = 被召回的次數（上限 10）
```

975 字的記憶，從沒被召回時長這樣：

```
day   0 → 975    day  28 → 440    day 112 → 239
day   7 → 693    day  35 → 401    day 168 → 197（落 T2）
day  14 → 567    day  56 → 328
day  21 → 491    day  90 → 264
```

保留率從 71% 一路升到 95%，約 162 天沉成 T2。

人遺忘是頭幾天掉得最狠、之後幾乎平掉 —— 等速的曲線是錯的。

### 為什麼是連續公式，不是階梯

早先的版本是離散階梯（每次抹 `25% × 0.84^n`）。它有個致命問題：**欠帳會累加**。

一條 T3 被反覆召回、半年沒被壓，`sinceDays` 累到 187 天，下一輪一次補 26 格 ——
975 字直接塌成 184 字，**掉 81%**。模型只看到「把這段經歷壓成一百多字」，
於是它把整段體會壓成一句殘缺的話，中間十六次提煉全部跳過。

連續公式沒有累積欠帳：任何一天算出來的，就是**那一天本來該有多長**。
中斷多久都不會斷崖 —— 實測最狠的一步跌幅永遠等於第一步（28.9%）。

### 想起越多次，時間軸越長

`s = 1.2^R` 把整條時間軸拉長 —— 這是真延長，不是延後一格：

| 被召回 | 落 T2 所需 |
|:--:|---:|
| 0 次 | 162 天 |
| 5 次 | 403 天 |
| 10 次 | **1002 天** |

同一條記憶，被想起十次之後能活近三年才變梗概。

<details>
<summary>跟艾賓浩斯比</summary>

| 天 | 1 | 7 | 21 | 56 | 90 |
|---|---|---|---|---|---|
| 艾賓浩斯 | 44% | 24% | 17% | 12% | 11% |
| 本插件 | 94% | 71% | 50% | 34% | 27% |

形狀同向，整體慢約 2–3 倍 —— 記的是有意義的內容，不是無意義音節。
（`19/81 ≈ 0.2346` 是嚴格貼合艾賓浩斯的係數，但七天就掉 38.5% 太狠，所以用了 0.14。）
</details>

## 模型碰不到 T2

```
模型 → condense(id, title, body)
           │
        結果 ≤ 200 字？
        ├─ 是 → T2（系統產生，終態）
        └─ 否 → 還是 T3，等下一輪
```

`silt_remember` 的 `tier` 只接受 1 / 3 / 4 / 5，**`tier: 2` 會被直接拒絕**。

為什麼：如果模型能直接寫 T2，它就會繞過整條壓縮路徑，把自己想留的東西釘在終態上。

**插件決定「壓到多短」，模型決定「留下甚麼」。**

## 作廢：不改歷史，只加記錄

```
原條   T1 本人 2027-03 結婚        ← 內容一個字都不動
        voided: true
        voidedReason: 本人說記錯了，是 2027-06
        replacedBy: m-新那條的id
新條   T1 本人 2027-06 結婚
```

改寫是「歷史被抹掉」；作廢是「我當時知道的是這樣，後來發現不是」。

作廢後不進提示詞，但帳本和倉庫都留著，`recall` 還搜得到並標 `voided: true`。

### 三種「不再用」的差別

| 動作 | 誰觸發 | 意思 | 進提示詞 |
|---|---|:--:|:--:|
| 歸檔 | 插件 | 被壓縮掉了 | ❌ |
| 過期 | 時間 | T5 到期限 | ✅ 標 ⏰ |
| 作廢 | 本人一句話 | 事後發現錯了 | ❌ |

## 提示詞裡放什麼

三塊：系統命令一行、**我是誰**、**仍記得的**。

```
系統命令：你的跨會話記憶與性格只走 silt_* 工具寫入；……

【我是誰】
- 我站在「能被檢查的解釋」那一邊，不在「宏大好看的說法」那一邊
- 繁體中文，句子短，先說結論再補一句理由
- 解釋要能被檢查：喜歡把東西拆到機制……

【仍記得的】
- T1 我的名字是 Ash（2026-11-12）
- T2 他信數據，不信說話順不順（2026-11-12）
- T3 記憶是重寫不是回放（2026-11-12）
（另有 16 條沒顯示 —— 用 silt_unseen 翻標題，找到再用 silt_recall 搜正文）
```

### 只放標題

記憶那部分**只有標題和日期，沒有正文**。正文靠 `silt_recall` 按需取。

這不是省字數的權宜之計，是實測出來的：只給標題時，模型看到「他信數據，不信說話順不順」，
被問「記得我信甚麼嗎」會自己 recall，把正文的原話撈回來。它知道該查，也查得回來。

同一個預算下，標題模式裝的條數是「標題＋正文」的兩倍以上。

### 塞不下就告訴它

記憶一定會有超額的一天。擠不進去時，末尾留一行明說還有幾條沒顯示：

```
（另有 16 條沒顯示 —— 用 silt_unseen 翻標題，找到再用 silt_recall 搜正文）
```

`silt_unseen` 把沒擠進去的標題一頁一頁攤開（預設 40 條/頁），回傳帶 `rest`：
`rest > 0` 就帶 `page: N+1` 繼續翻，`rest = 0` 就到底了。像翻書 —— 翻到對的標題就停手。

沒有這一行，模型會以為「我記得的就這些」，於是既不會去查，也不會承認自己有盲區。

### 條數由預算推

```
位置數 = injectBudget ÷ 50      （2000 字 ⇒ 40 個位置）
```

以前條數和字數是兩道閘分開調，互不知情：抬了預算卻被條數卡住，或反過來。
真正稀缺的是提示詞字數，所以條數由它推導。`injectCount` 已經不生效。

## 記憶怎麼存

只有一個真相：`<DSH_HOME>/silt/ledger.jsonl`，append-only、每筆哈希串起。

```
hash = sha256({v, seq, ts, kind, actor, payload, prev})
```

記憶、性格、底座、六維、快照全部是這本帳重放出來的投影。抽掉或改動任何一筆，
重放時鏈會斷在那一點 —— 頁面標紅、回滾停用。

每一次修改都帶 before/after 快照，可按 id 回滾。

以下參數開放給模型自行調整，但皆有硬範圍；超出時會被「夾到邊界」，而非拒絕。

| 參數 | 預設 | 範圍 | 說明 |
|---|:--:|:--:|---|
| `injectBudget` | 1800 | 600–3200 | 注入字數預算 —— 真正該調的是它 |

## 谷時值守

落在 DeepSeek 優惠時段（中午 12–14、晚間 18–次日 9，週末全天）而且有事到期時，
排一輪自主任務 —— 一個新會話，它自己決定要不要整理記憶、刷 B站、改自己。

**「不需要改」是有效決策。**

反思任務書是編號體：

```
1 狀態與節律   2 舊記憶壓縮   3 暫存區
4 記憶配額     5 自我與性格   6 未來的約定
7 對本人了解   8 底線         9 收尾
```

## 硬性界線

> 寫在代碼裡，模型改不了。

1. **技術隔離** —— 代碼、路徑、配置不入記憶。按結構特徵攔，不按主題詞（所以「她寫 Python」照樣記得）。
2. **不可靜默抹除** —— 哈希鏈，見上一節。
3. **不能捏造** —— 每筆記憶的證據由插件從寫入那次呼叫取得，模型給不了。
4. **不留憑據** —— 身份證、卡號按形狀攔。
5. **能加不能改** —— 寫錯了再寫一條對的，或作廢舊的。

## 對比其它方案

市面的 agent 記憶系統大多在解決「怎麼存更多、怎麼找更準」。這個插件在解決第三件事：
**怎麼讓記下的東西自己演變 —— 變短、變淡、變錯、變過期，而且每一步都留痕。**

分層、遺忘曲線、記憶整併這些並不新鮮。不一樣的是：

| | 差別 |
|---|---|
| **遺忘的是內容** | 別人的衰減只影響排序與踢出；這裡的 T3 是真的在變短 |
| **預測有到期日** | 過期後仍留在眼前逼你處理，不會悄悄爛掉 |
| **作廢是完整機制** | 很多方案根本沒有矛盾消解，錯了的事一直掛著 |
| **一條對一條** | 不把幾條合併成 gist，換來壓縮史完整可追 |
| **分層按生命週期** | 不是熱/溫/冷，是「永遠為真 / 梗概 / 會變淡」 |

**沒有的**：向量檢索（語義相近但字面不同搜不到）、矛盾自動檢測、元記憶、多用戶隔離。

## 界線說明

這個插件假設模型會誠實判斷「這值不值得記」。它防得住格式、憑據外洩、靜默篡改，
防不住模型把不重要的事寫得很多。

真正在管品質的是**上限、衰減、壓縮、作廢** —— 不是規則的數量。
