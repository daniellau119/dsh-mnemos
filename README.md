# dsh-mnemos

[English](README.en.md)

> 跨會話記憶與人格插件 · 版本 `v1.7.0` · 2026-11-15

`dsh-mnemos` 是為 DSH 宿主進程打造的長期記憶與人格成長引擎。它讓模型擁有一份會自我演化、分層沉澱、可被追問的記憶，以及一張由對話親手「長出來」的性格卡。

模型每一輪對話都會忘記上一輪。這個插件給它一個跨會話的記憶倉庫，和一個會生長的性格卡。

它不只解決「記住名字」，還解決四件事：

- **會變淡** —— 三年前的事不該跟今天說的一樣亮
- **會沉澱** —— 一段經歷慢慢收成一句梗概
- **會過期** —— 「下個月要結婚」過了就該去問
- **會出錯** —— 本人說「我說錯了」時，舊的要能作廢且留痕

整個系統的取捨，可以濃縮成四句話：

1. **唯一真相是帳本**  
   所有狀態（記憶、性格、六維、設定）皆由 `ledger.jsonl` 重放而成，沒有第二份可被隨手改寫的狀態檔。

2. **模型能加，不能改**  
   刪除、回滾、匯入是「本人」的權限；模型只能寫入新記憶，或透過 `mnemos_void` 標記「不成立了」。

3. **怎麼記由插件決定，記什麼由模型決定**  
   字數上限、衰減公式、壓縮節奏全部寫死在程式碼裡；模型的自由度只在內容、層級、維度與重要性。

4. **壓縮是前快後慢的**  
   一條經歷被反覆重講，越壓越輕，最終沉澱成一句話的「大概」。

## 記憶分五層

| | 是甚麼 | 上限 | 半衰期 | 進提示詞 |
|:--:|---|:--:|:--:|:--:|
| **T1** | 永久為真的事實（名字、生日、立場） | 100 | 100 年 | ✅ |
| **T2** | 經歷沉澱下來的梗概 | 200 | 400 天 | ✅ |
| **T3** | 值得留住的經歷 | 1000 | 112 天 | ✅ |
| **T4** | 暫存區：拿不準值不值得記 | 300 | 3 天 | ❌ |
| **T5** | 預測：還沒發生、有期限 | 400 | — | ✅ 過期也留 |

**T4 是緩衝，不是垃圾桶** —— 不進提示詞，被翻出來 3 次才升 T3，沒人提就自己散。

**T5 過期不是終點** —— 過期後仍留在提示詞裡，標 `⏰已過期`，逼模型去問結果。
只有被作廢才真正離開。

```
- T5 本人 12 月 20 日結婚（2026-11-15） — 到期日 2026-12-20 ⏰已過期
```

## 壓縮：前快後慢

T3 每 7 天壓一次，但**每次抹掉的幅度自己也在衰減**（`25% × 0.84^n`）：

```
975 → 731 → 578 → 476 → 405 → 355 → 318 → 290
    → 268 → 252 → 239 → 228 → 220 → 213 → 208 → 199（T2）
```

保留率從 75% 一路升到 98%，走完要 16 輪、112 天。

人遺忘是頭幾天掉得最狠、之後幾乎平掉 —— 等速的曲線是錯的。

被想起來的記憶壓得更慢：每被召回一次，時鐘往回撥 3.5 天。

<details>
<summary>跟艾賓浩斯比</summary>

| 天 | 1 | 7 | 21 | 56 | 90 |
|---|---|---|---|---|---|
| 艾賓浩斯 | 44% | 24% | 17% | 12% | 11% |
| 本插件 | 100% | 75% | 61% | 27% | 20% |

形狀相關 0.97，整體慢約 2 倍 —— 記的是有意義的內容，不是無意義音節。
</details>

## 模型碰不到 T2

```
模型 → condense(id, title, body)
           │
        結果 ≤ 200 字？
        ├─ 是 → T2（系統產生，終態）
        └─ 否 → 還是 T3，等下一輪
```

`mnemos_remember` 的 `tier` 只接受 1 / 3 / 4 / 5，**`tier: 2` 會被直接拒絕**。

為什麼：如果模型能直接寫 T2，它就會繞過整條壓縮路徑，把自己想留的東西釘在終態上。

**插件決定「壓到多短」，模型決定「留下甚麼」。**

## 作廢：不改歷史，只加記錄

```
原條   T1 本人 2027-03 結婚        ← 內容一個字都不動
        voided: true
        voidedReason: 本人說記錯了，是 2027-06
        replacedBy: m-新那條的id
新條   T1 本人 2027-06 結婚
```

改寫是「歷史被抹掉」；作廢是「我當時知道的是這樣，後來發現不是」。

作廢後不進提示詞，但帳本和倉庫都留著，`recall` 還搜得到並標 `voided: true`。

### 三種「不再用」的差別

| 動作 | 誰觸發 | 意思 | 進提示詞 |
|---|---|:--:|:--:|
| 歸檔 | 插件 | 被壓縮掉了 | ❌ |
| 過期 | 時間 | T5 到期限 | ✅ 標 ⏰ |
| 作廢 | 本人一句話 | 事後發現錯了 | ❌ |

## 記憶怎麼存

只有一個真相：`<DSH_HOME>/mnemos/ledger.jsonl`，append-only、每筆哈希串起。

```
hash = sha256({v, seq, ts, kind, actor, payload, prev})
```

記憶、性格、底座、六維、快照全部是這本帳重放出來的投影。抽掉或改動任何一筆，
重放時鏈會斷在那一點 —— 頁面標紅、回滾停用。

每一次修改都帶 before/after 快照，可按 id 回滾。

## 可調參數

以下參數開放給模型自行調整，但皆有硬範圍；超出時會被「夾到邊界」，而非拒絕。

| 參數 | 預設 | 範圍 | 說明 |
|---|:--:|:--:|---|
| `injectCount` | 12 | 1–24 | 每次注入幾條 |
| `injectBudget` | 1800 | 600–3200 | 注入字數預算 |
| `reflectionEveryHours` | 24 | 6–72 | 多久反思一次 |
| `biliEveryHours` | 20 | 6–72 | 多久刷一次 B 站 |
| `dutyMaxPerDay` | 2 | 1–4 | 每天最多幾輪值守 |
| `tier4TtlDays` | 3 | 0–90 | 暫存區保留天數（0 = 不過期） |

刷 B 站另有白名單參數（`perDay`、`fetchPerRound`、`keywords` 等），帳號、私信、自動評論等敏感項目由本人掌握，不開放模型調整。

## 記錄類型

`ledger.jsonl` 裡只有這幾種記錄，每筆都由誰寫是固定的。

| kind | 誰寫 | 說明 |
|---|---|---|
| `genesis` | plugin | 帳本誕生／重置 |
| `memory.write` | model | 新記憶（T1 / T3 / T4 / T5） |
| `memory.condense` | model | 壓縮一條 T3 |
| `memory.compress` | plugin | 產生 T2 的唯一通道 |
| `memory.upgrade` | plugin | T4 升級為 T3 |
| `memory.void` | model | 標記作廢 |
| `persona.revise` | model | 修訂性格卡 |
| `persona.foundation` | user | 改性格底座 |
| `understanding.revise` | model | 六維打分 |
| `inject.profile` | model | 調注入量 |
| `rhythm.profile` | model | 調節律 |
| `rollback` | user | 回滾快照 |
| `chain.repair` | user | 封存斷鏈 |

帳本裡另有 `memory.revise`、`memory.forget`、`origin.set` 三種舊記錄，是已移除能力的殘留，重放時照樣讀得過，但不再產生新的。

## 谷時值守

落在 DeepSeek 優惠時段（中午 12–14、晚間 18–次日 9，週末全天）而且有事到期時，
排一輪自主任務 —— 一個新會話，它自己決定要不要整理記憶、刷 B站、改自己。

**「不需要改」是有效決策。**

反思任務書是編號體：

```
1 狀態與節律   2 舊記憶壓縮   3 暫存區
4 記憶配額     5 自我與性格   6 未來的約定
7 對本人了解   8 底線         9 收尾
```

## 硬性界線

> 寫在代碼裡，模型改不了。

1. **技術隔離** —— 代碼、路徑、配置不入記憶。按結構特徵攔，不按主題詞（所以「她寫 Python」照樣記得）。
2. **不可靜默抹除** —— 哈希鏈，見上一節。
3. **不能捏造** —— 每筆記憶的證據由插件從寫入那次呼叫取得，模型給不了。
4. **不留憑據** —— 身份證、卡號按形狀攔。
5. **能加不能改** —— 寫錯了再寫一條對的，或作廢舊的。

## 對比其它方案

市面的 agent 記憶系統大多在解決「怎麼存更多、怎麼找更準」。這個插件在解決第三件事：
**怎麼讓記下的東西自己演變 —— 變短、變淡、變錯、變過期，而且每一步都留痕。**

分層、遺忘曲線、記憶整併這些並不新鮮。不一樣的是：

| | 差別 |
|---|---|
| **遺忘的是內容** | 別人的衰減只影響排序與踢出；這裡的 T3 是真的在變短 |
| **預測有到期日** | 過期後仍留在眼前逼你處理，不會悄悄爛掉 |
| **作廢是完整機制** | 很多方案根本沒有矛盾消解，錯了的事一直掛著 |
| **一條對一條** | 不把幾條合併成 gist，換來壓縮史完整可追 |
| **分層按生命週期** | 不是熱/溫/冷，是「永遠為真 / 梗概 / 會變淡」 |

**沒有的**：向量檢索（語義相近但字面不同搜不到）、矛盾自動檢測、元記憶、多用戶隔離。

## 界線說明

這個插件假設模型會誠實判斷「這值不值得記」。它防得住格式、憑據外洩、靜默篡改，
防不住模型把不重要的事寫得很多。

真正在管品質的是**上限、衰減、壓縮、作廢** —— 不是規則的數量。
